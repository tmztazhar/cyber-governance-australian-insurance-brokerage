# Access Control Policy
## Project: Cyber Security Governance Framework for an Australian Insurance Brokerage
## Organisation: HarbourShield Insurance Brokers Pty Ltd

### Document Owner : Operations Manager
### Approved By : Managing Director
### Version : 1.0
### Document Status : Portfolio Project – Fictional Business Scenario

## 1. Purpose
The purpose of this Access Control Policy is to define how HarbourShield Insurance Brokers Pty Ltd manages access to business systems, customer information, insurance documents, financial records, and company data.

Access control is important because HarbourShield handles sensitive customer and insurance-related information. Unauthorised access could lead to privacy breaches, financial fraud, business disruption, reputational damage, and loss of customer trust.

This policy supports the principle of least privilege, where users are only given access required to perform their job responsibilities.

## 2. Policy Objectives
The objectives of this policy are to:
1. Ensure access to systems and information is approved and business-justified.
2. Limit access based on user roles and responsibilities.
3. Reduce the risk of unauthorised access to sensitive information.
4. Ensure user access is removed promptly when no longer required.
5. Protect privileged and administrator accounts.
6. Support regular access reviews.
7. Improve accountability for system owners and users.

## 3. Scope
This policy applies to:
- All employees, contractors, temporary workers, and authorised third parties.
- All business systems used by HarbourShield.
- Microsoft 365, SharePoint, OneDrive, insurance CRM, Xero, WordPress, insurer portals, and other business applications.
- Company laptops, cloud platforms, collaboration tools, and remote access services.
- Customer, employee, supplier, insurer, policy, claims, finance, and operational information.
- Outsourced IT providers and third-party vendors with access to HarbourShield systems.

## 4. Access Control Principles
HarbourShield’s access control approach is based on the following principles:

| Principle | Description |
| --- | --- |
| Least privilege | Users should only receive access needed for their role. |
| Need to know | Sensitive information should only be accessible to authorised users with a valid business need. |
| Unique user account | Each user should have their own account where possible. |
| Accountability | User activity should be traceable to an individual account. |
| Timely removal | Access must be removed promptly when users leave or change roles. |
| Periodic review | Access rights should be reviewed regularly. |
| Strong authentication | Critical systems should use strong passwords and multi-factor authentication. |

## 5. User Account Requirements
All users must have an approved account before accessing HarbourShield systems.

User account requirements include:
- Each user must have a unique account where the system allows it.
- Shared accounts should be avoided unless formally approved.
- User accounts must be created only after approval from the Operations Manager or relevant system owner.
- Accounts must be assigned based on the user’s role and responsibilities.
- Default access should be limited.
- Access to sensitive systems must be approved before use.
- User accounts must not be shared with other employees, contractors, family members, or external parties.
- Generic accounts must be reviewed and documented if they cannot be avoided.

## 6. Access Request Process
New access must follow an approval process.

The access request process should include:
1. User name and role.
2. System or application requested.
3. Type of access required.
4. Business reason for access.
5. Approval from the system owner or Operations Manager.
6. Implementation by the outsourced IT provider or system administrator.
7. Record of access granted.

Example access request table:
| Request Item | Example |
| --- | --- |
| User | New Insurance Broker |
| Access Required | Broker user access |
| Business Reason | Required to manage customer policies and renewals |
| Approval Owner | Operations Manager |
| Implemented By | Outsourced IT Provider / CRM Administrator |

## 7. Role-Based Access
Access should be assigned based on job role where possible.

Example role-based access model:

| Role | Typical Access |
| --- | --- |
| Managing Director | Management reports, high-level business systems, selected finance and governance documents. |
| Operations Manager | Microsoft 365 administration coordination, SharePoint, CRM administration, governance documents, risk register, asset register. |
| Insurance Broker | CRM customer records, insurer portals, policy documents, customer email communication. |
| Broker Team Lead | Broker access plus team oversight, selected reports, insurer portal management. |
| Claims Support / Admin | Customer documents, claims support files, selected CRM access. |
| Finance Manager | Xero, invoices, payment records, finance documents, selected supplier information. |
| Marketing Coordinator | WordPress, website content, marketing files, public enquiry submissions. |
| Outsourced IT Provider | Technical administration access required to support systems and users. |
| External Compliance Consultant | Limited access to compliance documents or evidence when required. |

Access should be adjusted if an employee changes role.
