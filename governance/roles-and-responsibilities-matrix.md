# Roles and Responsibilities Matrix

## Project: Cyber Security Governance Framework for an Australian Insurance Brokerage

### Organisation: HarbourShield Insurance Brokers Pty Ltd
### Document Owner : Operations Manager
### Version : 1.0
### Document Status : Portfolio Project – Fictional Business Scenario

## 1. Purpose
The purpose of this Roles and Responsibilities Matrix is to define who is responsible, accountable, consulted, and informed for key cyber security governance activities at HarbourShield Insurance Brokers Pty Ltd.

HarbourShield is a fictional Australian insurance brokerage with approximately 25 employees. The organisation does not have a dedicated internal cyber security team and relies on a combination of business leadership, operations management, system owners, employees, and an outsourced IT provider.

This matrix supports clear accountability for cyber security activities in a realistic small-to-medium business environment.

## 2. RACI Legend
This document uses a RACI model.

| RACI Term | Meaning |
| --- | --- |
| Responsible (R) | The person or role that performs the activity. |
| Accountable (A) | The person or role ultimately accountable for the outcome or decision. |
| Consulted (C) | The person or role that provides input before a decision or action. |
| Informed (I) | The person or role that should be kept updated. |

*Each activity should have at least one Responsible role and one Accountable role.*

## 3. Key Governance Roles

| Role | Description |
| --- | --- |
| Managing Director | Overall business owner accountable for cyber security risk, major decisions, and risk acceptance. |
| Operations Manager | Day-to-day coordinator of security governance, policies, risk register, access reviews, and incident escalation. |
| Outsourced IT Provider | External provider responsible for technical security controls, user account support, endpoint protection, backups, and incident containment support. |
| System Owner | Business owner responsible for the correct use, access, and data handling within a specific system. |
| Finance Manager | Owner of finance-related systems, payment processes, invoices, and finance fraud risk. |
| Broker Team Lead | Owner of broker team practices, customer information handling, insurer portal access, and client communications. |
| Marketing Coordinator | Owner of website content, enquiry forms, marketing platforms, and website-related supplier coordination. |
| Employees | All staff responsible for following security policies, protecting customer information, and reporting suspicious activity. |
| External Compliance Consultant | External adviser consulted when privacy, breach notification, insurance, or regulatory interpretation is required. |

## 6. Role-Based Responsibility Summary

### 6.1 Managing Director
The Managing Director is accountable for cyber security as a business risk.

Key responsibilities:
- Approve major security policies and governance documents.
- Review high and critical cyber risks.
- Approve major risk treatment decisions.
- Accept residual cyber risks where required.
- Approve high-risk suppliers.
- Decide whether serious incidents require external escalation.
- Support cyber security as part of business leadership.

### 6.2 Operations Manager
The Operations Manager is the day-to-day security governance coordinator.

Key responsibilities:
- Maintain the cyber risk register.
- Maintain the information asset register.
- Coordinate policy reviews.
- Coordinate access reviews.
- Coordinate incident response activities.
- Work with the outsourced IT provider on security improvements.
- Prepare security updates for the Managing Director.
- Track completion of security actions.

### 6.3 Outsourced IT Provider
The outsourced IT provider is responsible for technical implementation and support.

Key responsibilities:
- Create, modify, and disable user accounts.
- Configure MFA and technical security controls.
- Support endpoint protection.
- Apply software and security updates.
- Support backup and recovery.
- Assist with incident containment and investigation.
- Provide technical security recommendations.
- Notify the Operations Manager of significant technical risks.

### 6.4 System Owners
System owners are responsible for business-level control of their systems.

Key responsibilities:
- Approve appropriate user access.
- Review user access periodically.
- Confirm business justification for system permissions.
- Report unusual activity.
- Ensure sensitive data is handled correctly.
- Support risk assessment for their systems.

### 6.5 Employees
Employees are responsible for following security requirements in daily work.

Key responsibilities:
- Use approved systems and devices.
- Protect customer and company information.
- Use MFA where required.
- Report suspicious emails and security incidents.
- Avoid unauthorised software.
- Follow acceptable use and data handling policies.
- Complete assigned security awareness activities.

## 7. Escalation Responsibilities
Security issues should be escalated based on severity.

| Scenario | First Contact | Escalation Owner | Final Decision Owner |
| --- | --- | --- | --- |
| Suspicious email | Operations Manager | Outsourced IT Provider | Operations Manager |
| Lost or stolen laptop | Operations Manager | Outsourced IT Provider | Operations Manager |
| Suspected mailbox compromise | Operations Manager | Outsourced IT Provider | Managing Director |
| Accidental customer data disclosure | Operations Manager | External Compliance Consultant | Managing Director |
| Ransomware infection | Operations Manager | Outsourced IT Provider | Managing Director |
| Supplier breach notification | Operations Manager | External Compliance Consultant | Managing Director |
| Website compromise | Marketing Coordinator | Outsourced IT Provider | Operations Manager |
| Finance fraud attempt | Finance Manager | Operations Manager | Managing Director |

## 8. Review Frequency
This Roles and Responsibilities Matrix should be reviewed:
- At least annually.
- After a significant cyber security incident.
- After a major change in systems or suppliers.
- After business restructuring.
- When a new critical system is introduced.
- When responsibilities between HarbourShield and the outsourced IT provider change.
