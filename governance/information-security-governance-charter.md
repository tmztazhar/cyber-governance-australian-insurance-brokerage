# Information Security Governance Charter
## Project: Cyber Security Governance Framework for an Australian Insurance Brokerage
## Organisation: HarbourShield Insurance Brokers Pty Ltd

### Document Owner : *Operations Manager*
### Security Owner : *Managing Director*
### Version : *1.0*
### Document Status : *Portfolio Project – Fictional Business Scenario*

## 1. Purpose
The purpose of this Information Security Governance Charter is to define how HarbourShield Insurance Brokers Pty Ltd manages cyber security responsibilities, decision-making, risk ownership, policy governance, incident escalation, and security reporting.

HarbourShield is a fictional Australian insurance brokerage that handles customer personal information, insurance policy documents, claims information, financial records, and business customer data. Because the business relies heavily on cloud-based systems and outsourced IT support, clear security governance is required to protect customer trust, reduce operational disruption, and support responsible management of cyber security risks.

This charter provides a practical governance structure suitable for a small-to-medium insurance brokerage without assuming enterprise-level cyber security tooling or a dedicated internal security team.

## 2. Business Context
HarbourShield provides insurance brokerage services to individuals and small businesses in Australia. The company helps customers compare insurance products, submit applications, manage policy renewals, and communicate with insurers.

The organisation has approximately 25 employees and operates using a hybrid work model. Most systems are cloud-based, including Microsoft 365, SharePoint, OneDrive, a cloud-based insurance CRM, Xero, and a WordPress website.

The business depends on outsourced IT support for system administration, endpoint support, user access management, and technical security controls.

## 3. Governance Objectives
The objectives of this charter are to:
1. Define accountability for cyber security decisions.
2. Establish clear ownership of information security risks.
3. Support practical alignment with ISO/IEC 27001-style governance principles.
4. Improve visibility of cyber risks to business leadership.
5. Ensure security policies are approved, reviewed, and maintained.
6. Establish a clear escalation path for cyber security incidents.
7. Support consistent management of third-party technology and service providers.
8. Promote security awareness across all employees.

## 4. Scope
This charter applies to:
1. All employees, contractors, and temporary workers of HarbourShield.
2. All business systems used to process, store, or transmit company or customer information.
3. All customer, employee, supplier, insurer, policy, claims, and financial information.
4. All company-owned laptops, mobile devices, cloud systems, and collaboration platforms.
5. Outsourced IT providers and third-party systems that support business operations.
6. Security policies, procedures, risk assessments, and incident response activities.

## 5. Out of Scope
The following items are outside the scope of this portfolio governance charter:
- Full ISO/IEC 27001 certification.
- Formal external audit.
- Penetration testing.
- Security operations centre implementation.
- Enterprise GRC platform implementation.
- APRA-regulated entity compliance audit.
- Legal advice on Australian privacy, insurance, or financial services obligations.

## 6. Governance Principles
HarbourShield’s cyber security governance is based on the following principles:

| Principle | Description |
| --- | --- |
| Business ownership | Cyber security risk is a business risk, not only an IT issue. |
| Practical security | Controls should be realistic for an SME environment. |
| Least privilage | Users should only receive access required for their role. |
| Accountability | Each key system and information asset should have an accountable owner. |
| Risk-based decisions | Security decisions should be based on likelihood, impact, and business context. |
| Continuous improvement | Security controls should be reviewed and improved over time. |
| Incident readiness | The business should know how to respond before an incident occurs. |
| Supplier awareness | Third-party providers should be reviewed based on the information and access they handle. |

## 7. Governance Structure
HarbourShield does not have a dedicated internal cyber security team. Security governance is managed through a small business governance model involving leadership, operations, outsourced IT, and system owners.

| Governance Role | Responsibility |
| --- | --- |
| Managing Director | Overall accountability for cyber security risk and approval of major security decisions. |
| Operations Manager | Day-to-day owner of security governance documentation, policy coordination, and risk register maintenance. |
| Outsourced IT Provider | Technical implementation of security controls, user access management, endpoint support, backups, and system monitoring. |
| Department / System Owners | Responsible for appropriate use, access review, and data handling within their business area. |
| Employees | Responsible for following security policies, reporting incidents, and protecting customer information. |
| External Compliance Consultant | Provides guidance on privacy, insurance, and regulatory expectations when required. |

## 8. Roles and Responsibilities
### 8.1 Managing Director
The Managing Director is accountable for the overall cyber security posture of HarbourShield.

Responsibilities include:
- Approving the information security governance charter.
- Approving major security policies.
- Reviewing high and critical cyber risks.
- Approving risk treatment decisions that require business investment.
- Supporting a security-aware culture.
- Ensuring cyber security is considered in business decisions.
- Approving incident escalation to external parties where required.

### 8.2 Operations Manager
The Operations Manager is responsible for coordinating day-to-day security governance activities.

Responsibilities include:
- Maintaining the cyber risk register.
- Coordinating security policy reviews.
- Maintaining the information asset register.
- Coordinating incident response documentation.
- Working with outsourced IT to track security improvements.
- Preparing periodic cyber security updates for management.
- Coordinating staff security awareness activities.
- Ensuring terminated employees are removed from business systems.

### 8.3 Outsourced IT Provider
The outsourced IT provider is responsible for implementing and supporting technical security controls.

Responsibilities include:
- Managing user accounts and access permissions.
- Enforcing multi-factor authentication where supported.
- Supporting endpoint security controls.
- Applying system and software updates.
- Managing backup configuration and recovery support.
- Assisting with incident investigation and containment.
- Providing technical recommendations to improve security.
- Reporting significant security issues to the Operations Manager.

### 8.4 System Owners
System owners are responsible for the business use and access control of key systems.

Examples of system owners include:
| System | System Owner |
| --- | --- |
| Insurance CRM | Operations Manager |
| Microsoft 365 | Operations Manager with outsourced IT support |
| Xero | Finance Manager |
| WordPress Website | Marketing Coordinator |
| SharePoint / OneDrive | Operations Manager |
| Insurer Portals | Broker Team Lead |

Responsibilities include:
- Reviewing user access periodically.
- Ensuring only authorised staff can access sensitive information.
- Reporting unusual system activity.
- Confirming whether access requests are business-justified.
- Supporting data retention and secure handling expectations.

### 8.5 Employees
All employees are responsible for protecting company and customer information.

Responsibilities include:
- Following security policies and procedures.
- Using strong passwords and multi-factor authentication.
- Reporting suspicious emails, account compromise, lost devices, or data exposure.
- Avoiding unauthorised sharing of customer or policy information.
- Using approved business systems for company work.
- Completing assigned security awareness activities.
- Not installing unauthorised software on work devices.

## 9. Security Decision-Making
Security decisions should be based on business risk, customer impact, operational impact, and cost.

The following decision-making approach should be used:
| Decision Type | Decision Owner |
| --- | --- |
| Routine access requests | System Owner and Operations Manager |
| New user onboarding | Operations Manager and outsourced IT |
| User termination access removal | Operations Manager and outsourced IT |
| Security policy approval | Managing Director |
| High-risk supplier approval | Managing Director |
| Critical incident escalation | Managing Director |
| Technical security configuration | Outsourced IT with Operations Manager approval |
| Risk acceptance | Managing Director |

## 10. Cyber Risk Management
HarbourShield maintains a cyber risk register to identify, assess, treat, and monitor key information security risks.

Each risk should include:
- Risk ID.
- Risk description.
- Affected asset or process.
- Threat scenario.
- Likelihood.
- Impact.
- Inherent risk rating.
- Existing controls.
- Residual risk rating.
- Risk owner.
- Treatment plan.
- Target completion date.
- Status.

*Risk ratings should be reviewed at least every six months or after a significant incident, system change, supplier change, or business change.*

## 11. Risk Ownership
Cyber risks must have clear business ownership. Risk ownership does not mean the risk owner personally fixes every issue. It means the owner is accountable for understanding the risk, making decisions, requesting support, and ensuring treatment actions are tracked.

Example risk ownership model:
| Risk Area | Risk Owner |
| --- | --- |
| Business email compromise | Operations Manager |
| Customer data exposure | Operations Manager |
| Finance fraud | Finance Manager |
| CRM access misuse | Operations Manager |
| WordPress compromise | Marketing Coordinator with outsourced IT support
| Ransomware | Managing Director and outsourced IT provider |
| Supplier security failure | Managing Director |
| Former employee access | Operations Manager |

## 12. Policy Governance
HarbourShield maintains a small set of practical security policies suitable for an SME environment.

The policy pack includes:
- Information Security Policy.
- Access Control Policy.
- Acceptable Use Policy.
- Password and MFA Policy.
- Data Classification Policy.
- Backup and Recovery Policy.
- Incident Response Plan.
- Third-Party Security Review Checklist.

Policies should be:
- Written in plain business language.
- Approved by the Managing Director.
- Reviewed at least annually.
- Updated after significant incidents or business changes.
- Communicated to employees.
- Stored in a central company location.

## 13. Policy Exceptions
There may be situations where a business process cannot fully comply with a security policy.

Policy exceptions must be:
1. Documented
2. Justified by a business reason.
3. Reviewed by the Operations Manager.
4. Approved by the Managing Director if the risk is medium, high, or critical.
5. Time-limited where possible.
6. Reviewed before renewal.

Example exceptions include:
- Temporary access to a system for a contractor.
- Temporary use of a legacy system that does not support MFA.
- Delayed patching due to business-critical system compatibility.
- Temporary manual process during system outage.

## 14. Security Reporting
The Operations Manager should provide a quarterly cyber security update to the Managing Director.

The report should include:
| Reporting Area | Example Metric |
| --- | --- |
| Open cyber risks | Number of high, medium, and low risks |
| Access reviews | Number of systems reviewed |
| Incidents | Number and type of security incidents |
| MFA coverage | Percentage of users with MFA enabled |
| Backup status | Last successful backup and recovery test status |
| Security awareness | Staff completion status |
| Supplier reviews | Number of critical suppliers reviewed |
| Policy updates | Policies reviewed or updated |

The report should be written for business leaders, not only technical staff.

## 15. Incident Escalation
Employees must report suspected security incidents as soon as possible.

Examples of reportable incidents include:
- Suspicious emails or phishing attempts.
- Suspected mailbox compromise.
- Lost or stolen laptop.
- Unauthorised access to customer files.
- Ransomware or malware infection.
- Accidental email sent to the wrong recipient.
- Unusual CRM activity.
- Website compromise.
- Supplier security notification.

Incident escalation should follow this path:

Employee --> Operations Manager --> Outsourced IT Provider --> Managing Director --> External legal, regulatory, insurer, or customer notification if required

## 16. Third-Party Governance
HarbourShield relies on third-party systems and service providers. These suppliers may store, process, or access customer and business information.

Key suppliers include:
| Supplier Type | Example |
| --- | --- |
| Cloud productivity provider | Microsoft 365 |
| CRM provider | Insurance CRM vendor |
| Accounting provider | Xero |
| IT support provider | Managed IT provider |
| Website hosting provider | WordPress hosting company |
| Insurance partners | Insurance portals |
| Compliance adviser | External consultant |

Third-party security review should consider:
- Type of information handled.
- Level of system access.
- Use of MFA.
- Backup and recovery capability.
- Security certifications or assurance reports where available.
- Incident notification process.
- Data location and privacy considerations.
- Contractual security obligations.
- Termination and access removal process.

*Critical suppliers should be reviewed at least annually.*

## 17. Access Governance
User access should follow the principle of least privilege.

Access governance requirements include:
- Every user must have a unique account.
- Shared accounts should be avoided.
- MFA should be enabled for email, cloud systems, CRM, and finance systems where supported.
- New access must be approved by the relevant system owner.
- Access should be removed promptly when an employee leaves.
- Privileged access should be limited to authorised users only.
- System access should be reviewed at least every six months.
- External IT administrator access should be reviewed periodically.

## 18. Security Awareness
Employees are the first line of defence against phishing, fraud, data leakage, and social engineering.

HarbourShield should provide practical awareness guidance covering:
- Phishing and suspicious emails.
- Business email compromise.
- Password security and MFA.
- Secure handling of customer documents.
- Reporting incidents quickly.
- Avoiding unauthorised software.
- Safe use of cloud file sharing.
- Remote work security.

*Training should be simple, relevant, and repeated periodically.*

## 19. Review Cycle
This governance charter should be reviewed:
- At least annually.
- After a significant cyber security incident.
- After a major system change.
- After onboarding a critical supplier.
- After significant business growth or restructuring.
- When relevant legal, regulatory, or industry expectations change.
